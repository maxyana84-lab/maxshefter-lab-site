case study

Eight faults, one broken EKS ingress — found and fixed live

A store app behind the AWS Load Balancer Controller, with Ingress, Service and Deployment manifests broken on purpose. No ALB, 503s, failing HTTPS.

I deployed it as-is on a real EKS cluster and worked from symptoms to root causes using only kubectl, AWS APIs and controller logs.

EKSALB ControllerACMeksctlkubectl
→ full write-up and manifests on GitHub
  1. symptom

    Cluster up, nodes missing

    The node group sat at 0/2 instances with no obvious error. aws autoscaling describe-scaling-activities showed the account only allowed Free Tier instance types, so t3.medium failed silently. Switched to t3.small.

  2. diagnose

    No load balancer created

    Controller logs and kubectl describe ingress pointed to a wrong ingressClassName, a legacy class annotation, broken annotation quoting, an invalid scheme value and a placeholder certificate ARN.

  3. diagnose

    ALB up, but 503

    kubectl get endpoints was empty: the Service selector didn't match the Deployment labels. The Service type was also wrong for the target mode.

  4. result

    All 8 fixed, verified, torn down

    HTTP→HTTPS redirect and TLS handshake verified with a certificate imported into ACM. Wrote an incident report with safeguards, then deleted every resource to keep cost at zero.

how I work

Habits from years in production operations, now applied to cloud infrastructure.

Everything as code

Clusters, networks and pipelines live in git. If it can't be rebuilt from the repo, it isn't done.

Debug from symptoms

Logs, events and APIs first, guesses last. Every fix gets a root cause, not just a restart.

Least privilege

Short-lived credentials and narrow IAM roles. CI gets exactly the permissions it needs, nothing more.

Pay only for what runs

Lab environments are torn down when the work is done. Cost is part of the design.

how this site is deployed

Every change goes through a pipeline — no manual uploads, no stored cloud keys.

git push main └─ GitHub Actions (OIDC → short-lived IAM role, no secrets) ├─ stamp commit SHA into the page ├─ aws s3 sync site/ → S3 (private, Origin Access Control) ├─ cloudfront create-invalidation └─ smoke test: curl https://maxshefter-lab.online visitor → Route 53 → CloudFront (TLS via ACM, HTTP/3, security headers) └─ S3 origin infrastructure: 100% Terraform · ~$0.50/month
